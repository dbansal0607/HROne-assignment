# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33–38) | Grace period boundary logic drops `09:40:01`. The calculation converts difference to integer minutes before checking `minutes > 10`. For `09:40:01`, elapsed time is 601s = 10.016 min; `int()` is 10; `10 > 10` is False, returning 0. R2 explicitly mandates 10. | Test with shift 09:30, punch-in `09:40:01 IST`. Returns 0 instead of required 10. | Computed elapsed seconds: `elapsed_sec = int((punch_in_ist - shift_start_ist).total_seconds())`. If `elapsed_sec > 600`, `late_minutes = elapsed_sec // 60`; otherwise `0`. |
| 2 | `compute_late_minutes` (lines 33–38) | Timezone blindness. `punch_in.replace(hour=h, minute=m)` modifies the hour of a UTC datetime with IST shift hours, comparing UTC to IST without timezone conversion. | When `punch_in` is UTC `03:58:00Z` (09:28 IST), `start` becomes `09:30:00Z`, computing -5.5 hours. | Converted `punch_in` to IST (`Asia/Kolkata` / UTC+05:30) before extracting date and constructing the IST shift start datetime. |
| 3 | `compute_late_minutes` (lines 33–38) | No lower bound check for early punch-ins. An early punch-in could produce negative elapsed seconds if not properly guarded. | Punch in at 09:15 for a 09:30 shift; `(punch_in - start)` is negative. | Guarded condition: if `elapsed_sec <= 600` (including negative), return `0`. |
| 4 | `compute_work_hours` (lines 40–42) | Python's built-in `round()` uses round-half-to-even (banker's rounding) and floating-point arithmetic. R4 strictly specifies rounding to 2 decimals half-up. | Test duration yielding half-way cases (e.g., `2.555` -> rounds to `2.55` in Python `round()`, but requires `2.56` half-up). | Used `Decimal` with `ROUND_HALF_UP`: `Decimal(str(seconds / 3600)).quantize(Decimal('0.01'), rounding=ROUND_HALF_UP)`. |
| 5 | `compute_overtime` (lines 44–48) | Missing 30-minute minimum threshold. R3 requires overtime to be counted only when >= 30 minutes; otherwise 0. | 6 | `compute_overtime` (lines 44–48) | Overnight shift `shift_end` is placed on the punch-in calendar date `date_str`. ### Examined and Verified as NOT Defects:
1. **`EmployeeIn` default shift values (`shift_start = "09:30"`, `shift_end = "18:30"`)**: Matches openapi.yaml specification defaults.
2. **`PunchInIn.punched_at = None`**: Defaults to the server clock if omitted, which is explicitly expected by the contract.
3. **`PunchInIn.status = "PRESENT"`**: Defaulting to `PRESENT` aligns with the specification.
4. **No endpoints to create `ABSENT` or `LEAVE` records directly**: Section 5 of `PROBLEM_STATEMENT.docx` explicitly states: "No endpoint creates `ABSENT` or `LEAVE` records. Seeded back-office data, or a correction."
5. **No authentication on `regularized_by` in `PATCH`**: Section 5 of `PROBLEM_STATEMENT.docx` explicitly confirms: "`by`: string (free text, no authentication in this assignment)."
